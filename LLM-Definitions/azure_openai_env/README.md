# Azure OpenAI (environment-configured)

Azure OpenAI / Azure AI Foundry chat deployment configured by the container environment: AZURE_OPENAI_API_KEY, AZURE_OPENAI_RESOURCE and AZURE_OPENAI_DEPLOYMENT decide which key, project and model a container uses, so one published image serves any Azure deployment. Defaults to the gpt-5.6-luna deployment.

This definition was generated by the [Model Definition Builder](../../Model-Definition-Builder/README.md) from `definition.yaml` — edit that file and run `mdb generate azure_openai_env` instead of editing the generated files by hand.

## Configuration options

The following options can be supplied at scoring time through the `options` input (see the [LLM-Definitions README](../README.md) for the format):

| Option | Default | Range | Description |
| ------ | ------- | ----- | ----------- |
| `reasoning_effort` | medium | minimal | low | medium | high | maximum | How much effort a reasoning model spends thinking before it answers. Higher levels improve quality on hard problems at the cost of latency and tokens. The normalized level is translated to what the specific provider supports (e.g. OpenAI reasoning_effort, Anthropic effort, Gemini thinking_level). |
| `max_completion_tokens` | 4000 | 1 - 128000 (includes reasoning tokens) | Limits the total tokens generated by a reasoning model, including internal reasoning tokens. Use this instead of max_tokens for reasoning models. |

## Deployment

What the SCR container needs from its environment (the caller-side options are in the table above):

- `AZURE_OPENAI_RESOURCE` is **required**: the Azure resource the container calls (any host flavor - `<res>.openai.azure.com`, `<res>.cognitiveservices.azure.com`, `<res>.services.ai.azure.com` - or the bare resource name). This definition commits no resource, so one image serves any Azure resource.
- `AZURE_OPENAI_API_VERSION` is optional: unset keeps what this definition bakes (nothing: the GA route), a version selects the legacy `/openai/deployments/<name>/...` route that some resources or org policies still require, and an explicitly *empty* value forces the GA `/openai/v1/...` route. A v1-only resource answers the legacy route with a bare 401 and no body - that is the symptom to look for. `AZURE_OPENAI_ENDPOINT` overrides the whole URL.
- `AZURE_OPENAI_API_KEY` supplies the key (an `API_KEY` option, when present, still wins) and `AZURE_OPENAI_DEPLOYMENT` the deployment, defaulting to `gpt-5.6-luna`. This definition declares no `API_KEY` option: the container, not the caller, holds the key.
