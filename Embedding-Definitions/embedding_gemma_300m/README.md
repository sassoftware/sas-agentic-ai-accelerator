# Embedding Gemma 300M

EmbeddingGemma is a 300M parameter, state-of-the-art for its size, open embedding model from Google, built from Gemma 3 (with T5Gemma initialization) and the same research and technology used to create Gemini models. EmbeddingGemma produces vector representations of text, making it well-suited for search and retrieval tasks, including classification, clustering, and semantic similarity search. This model was trained with data in 100+ spoken languages.

This definition was generated by the [Model Definition Builder](../../Model-Definition-Builder/README.md) from `definition.yaml` — edit that file and run `mdb generate embedding_gemma_300m` instead of editing the generated files by hand.

## Configuration options

The following options can be supplied at scoring time through the `options` input (see the [LLM-Definitions README](../README.md) for the format):

| Option | Default | Range | Description |
| ------ | ------- | ----- | ----------- |
| `Embedding_Mode` | query | query | document | Whether the text is embedded as a query (for retrieval) or as a document (for storage/indexing). Using the matching mode on both sides improves retrieval quality. |
| `Embedding_Length` | 384 | 384 | The length of the returned embedding vector. |
| `Input_Token_Limit` | 256 | 256 | The limit of input tokens for the embedding model. |

## Deployment

What the SCR container needs from its environment (the caller-side options are in the table above):

- The weights are baked into the image at build time; the container needs no provider connection and no key.

## Register and publish

```bash
mdb register embedding_gemma_300m
mdb publish embedding_gemma_300m -d <your-destination>
```

Or do both in one step with `mdb ship embedding_gemma_300m`. The publishing destination can also come from `SAS_PUBLISH_DESTINATION` in your `.env`.
